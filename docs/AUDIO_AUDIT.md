# Audio audit and calibration guide

The audio audit measures the fidelity of the conversion by comparing renders
generated in Ableton Live or in Pro Tools from an AAF, sample by sample, with
the expected reference audio. This document describes the steps of preparation,
rendering and checking of the calibration package. In this guide, `{{PACOTE}}`
stands for the package folder; in the `INSTRUCOES.md` copy that
`scripts/prepare_audio_audit.py` writes into the package, it already appears
replaced by the real path.

## How to generate the package

The calibration package is generated by the script
`scripts/prepare_audio_audit.py`, run from the root of the repository with the
Python of the environment where aafton is installed:

```powershell
python scripts/prepare_audio_audit.py --output-dir out/audio-audit
```

Options defined by the script:

- `--output-dir PATH`: path of the folder where the calibration package is
  created (mandatory). If the destination folder already exists and holds
  previous renders or exports in the `renders/` or `reexport/` folders, the run
  is interrupted to preserve the existing files.
- `--include-structural-corpus`: also imports, with `--fades absorb`, the Pro
  Tools test AAF `tests/fixtures/aaf/TESTE_AFF_PROTOOLS.aaf` (14 tracks), whose
  media is digital silence; the media comes from the `teste_aaf` folder of the
  corpus, pointed to by `AAFTON_CORPUS_DIR` (without it, `.local/corpus/teste_aaf`
  in the repository), which is not distributed. It serves only to check the
  structure, never as a sound proof.

## What the package holds

The generated package gathers the test structure, the reference files and the
folders organized for the human renders:

- `calibracao/`:
  - `calibracao.aaf`: calibration AAF made of seven audio tracks (`CAL_MONO`,
    `CAL_OFFSET`, `CAL_GAIN`, `CAL_INTERLEAVED`, `CAL_SPLIT`, `CAL_FADES` and
    `CAL_TWO_CLIPS`).
  - `calibracao.als`: Live project generated by the import of the AAF with
    `--fades keep` and start at 01:00:00:00.
  - `calibracao.aafton.json`: sidecar of the project with the temporal anchors
    and the declared limits of the clips.
  - `estereo-fonte.aaf`: AAF of a single track, `CAL_INTERLEAVED`, generated by
    the calibration factory.
  - `estereo.als`: Live project imported from that AAF.
  - `estereo.aafton.json`: sidecar of `estereo.als`, used in the third audit
    command.
  - `Samples/`: mono and stereo WAV files referenced by the clips of the
    calibration session.
  - `expected/`: WAV files with the expected reference audio for each
    calibration track.
  - `estereo-produto.aaf`: AAF generated by the CLI exporter from
    `estereo.als` for the validation of the stereo export.
  - `expected-estereo/`: expected reference audio for the `CAL_INTERLEAVED`
    track.
  - `sanity.json` and `sanity.md`: report of the previous check of the reference
    against itself.
- `renders/`: folders prepared to receive the renders:
  - `renders/live/calibracao/`: renders generated in Ableton Live from
    `calibracao.als`.
  - `renders/protools/calibracao/`: bounces prepared in Pro Tools from
    `calibracao.aaf`.
  - `renders/protools/calibracao-brutos/`: raw bounces recorded directly by Pro
    Tools before the normalization of the names.
  - `renders/protools/estereo-produto/`: bounce in Pro Tools from
    `estereo-produto.aaf`.
- `map-calibracao.json`: mapping between the tracks and the pairs of reference
  and candidate WAV files.
- `map-estereo-produto.json`: mapping for the stereo product track.
- `INSTRUCOES.md`: copy of this guide, with the package folder already filled
  in.
- `bundle.json`: manifest with the metadata and the state of the generated
  package.
- `reports/`: destination folder of the audit reports in Markdown and JSON
  generated by the CLI.
- `real/` (optional, present when `--include-structural-corpus` is given):
  folder with `TESTE_AFF_PROTOOLS-absorb.als` and the structural mask
  `mask-absorb.json`.

## What to render in Live and in Pro Tools, and how

### 1. Pro Tools — calibration

Session settings in Pro Tools:

- Sample rate of 48 kHz, 32 bit float resolution, frame rate of 25 fps and
  start timecode at 01:00:00:00.
- Import `calibracao/calibracao.aaf`: select "Copy from source media", "Maintain
  absolute timecode values" and turn the rate conversion off (SRC). Relink the
  media in the `calibracao/Samples/` folder.
- Confirm that the `CAL_INTERLEAVED` track appears as stereo, with distinct L
  and R channels.
- Time selection on the ruler in Samples: relative start at 0 and length of
  192000 samples (4 seconds at 48 kHz).
- Track Bounce Offline settings: WAV 32 bit float format, 48 kHz, no
  normalization, no prefix and no "Pad To Frame Boundary". Expected BWF
  TimeReference: 172800000.
- Routing and export by track:
  - Mono tracks: `CAL_MONO`, `CAL_OFFSET`, `CAL_GAIN`, `CAL_FADES`,
    `CAL_TWO_CLIPS`, `CAL_SPLIT_L` and `CAL_SPLIT_R`. Output routed to Bus 1
    (Mono), bouncing each track on its own.
  - Stereo track: `CAL_INTERLEAVED`. Stereo output, panners at L100/R100 and
    stereo bounce.
- Save the raw files in `renders/protools/calibracao-brutos/`.
- After the render, build the stereo pair `CAL_SPLIT.wav` from the mono files
  `CAL_SPLIT_L` and `CAL_SPLIT_R` with no change of gain and no resampling, and
  organize the files in `renders/protools/calibracao/` with the matching names
  (`CAL_MONO.wav`, `CAL_OFFSET.wav`, `CAL_GAIN.wav`, `CAL_INTERLEAVED.wav`,
  `CAL_SPLIT.wav`, `CAL_FADES.wav`, `CAL_TWO_CLIPS.wav`).
- To validate the stereo export of the CLI (`estereo-produto.aaf`): import
  `calibracao/estereo-produto.aaf` in a session with the same settings
  (48 kHz, 32 bit float, 25 fps, start 01:00:00:00) and make the stereo bounce
  of `CAL_INTERLEAVED` (4 seconds) in the folder
  `renders/protools/estereo-produto/`.

### 2. Live — calibration and sessions with audio

Settings in Ableton Live:

- Device rate at 48 kHz.
- Open `calibracao/calibracao.als`.
- In the Export Audio/Video window:
  - Rendered Track: All Individual Tracks.
  - Start: 1.1.1.
  - Length: 1.0.0 (4 seconds at 60 BPM).
  - Format: WAV 32 bits, Encode PCM on, MP3 off, Normalize Off, No Dither,
    Convert to Mono Off, Loop Off.
  - Return and Master effects off.
  - Do not change faders, pan, Warp, gain nor fades.
  - Save the files in `renders/live/calibracao/`.
  - Live may export auxiliary tracks (such as Return A, Return B, Main). Move
    those files out of the candidate folder before running the audit, keeping
    in `renders/live/calibracao/` only the audio files declared in the map.

For sessions with real sound material, such as the TESTE_NOVO test case:

- The reference AAF is a Pro Tools re-export imported into Live with
  `--fades keep`.
- The same rendering guidelines apply: 25 fps, start timecode at 01:00:00:00
  (or the nominal timecode of the session), mono bounces through Bus 1 (Mono)
  and stereo pairs preserved, exporting in Live with All Individual Tracks
  without normalization or dither.

## Audit commands

After organizing the rendered files and checking the coverage of the tracks,
run the CLI commands. Do not change thresholds to obtain a pass.

```powershell
$pacote = '{{PACOTE}}'

aafton audit-audio --reference "$pacote/calibracao/expected" --candidate "$pacote/renders/live/calibracao" --sidecar "$pacote/calibracao/calibracao.aafton.json" --map "$pacote/map-calibracao.json" --mode keep --release-mask 64 --report "$pacote/reports/calibracao-live.md" --json "$pacote/reports/calibracao-live.json"

aafton audit-audio --reference "$pacote/calibracao/expected" --candidate "$pacote/renders/protools/calibracao" --sidecar "$pacote/calibracao/calibracao.aafton.json" --map "$pacote/map-calibracao.json" --mode keep --report "$pacote/reports/calibracao-protools.md" --json "$pacote/reports/calibracao-protools.json"

aafton audit-audio --reference "$pacote/calibracao/expected-estereo" --candidate "$pacote/renders/protools/estereo-produto" --sidecar "$pacote/calibracao/estereo.aafton.json" --map "$pacote/map-estereo-produto.json" --mode keep --report "$pacote/reports/estereo-produto-protools.md" --json "$pacote/reports/estereo-produto-protools.json"
```

## How to read the results (keep and absorb)

### keep mode

The `keep` mode runs the strict sample by sample fidelity check:

- Rule of approval: total coverage of the tracks declared in the map (no
  missing or extra files), active audio mandatory both in the reference and in
  the candidate, zero lag (lag 0) and residual peak over the whole common
  window less than or equal to -90 dBFS.
- Silence is no proof: signals in which the reference or the candidate has no
  active audio above the tolerance fail the check.
- Cross-correlation and estimated gain are exclusively diagnostic in the
  report. The auditor never performs temporal alignment or gain compensation
  to approve a track.
- The `keep` mode refuses arbitrary time masks (`--mask`). The only exception
  admitted is `--release-mask`, which disregards up to N samples immediately
  after the end of each clip (to accommodate the declick ramp of Live), without
  touching any active span of a clip.
- Audio played outside the common window of the clips is also evaluated and
  must stay below -90 dBFS.

### absorb mode

The `absorb` mode is used when native fades are absorbed during the
conversion:

- It allows the application of time masks (`--mask`) to isolate the transition
  regions between native curves and linear ramps.
- It produces detailed reports with deviation measurements (`report_only`), but
  it does not issue an automatic approval of the sound signal.

### Generated reports

- Markdown report (`.md`): table summarizing tracks, channels, lag in samples,
  residual peaks in dBFS, RMS and the count of masked samples.
- JSON report (`.json`): structured data with detailed metrics per channel,
  using `null` to indicate values of -inf dBFS (absolute digital silence).

## Known limits

- Fixed tempo in the sidecar: the audit requires a nominal tempo of 60 BPM in
  the sidecar for an exact match between beats and seconds in the calculation
  of the start point of the session.
- File formats: support for WAV files in PCM (16, 24 and 32 bits) and IEEE
  float (32 and 64 bits), with reading of BWF chunks. RF64/BW64 formats,
  NaN/Infinity numeric values or structures with a truncated header are
  rejected with an error.
- End ramp of Live: the Live engine prolongs the reading for about 46 samples
  after the end of the clip, in a declick ramp. The `--release-mask 64`
  parameter covers that post-clip window without interfering with the internal
  content of the clips.
- Amplitude clipping in PCM in Pro Tools: on the AAF export in 24 bit PCM by
  Pro Tools, samples with amplitude above 0 dBFS in the original signal are
  clipped. The audit measures the real divergence without trying to mask the
  effect.
- Scope of the verification: the audit proves the match of the audio generated
  by Live and by Pro Tools from the imported AAF against the expected
  references. It does not cover internal plugin processing nor does it certify
  full round trip transparency of proprietary sessions.
